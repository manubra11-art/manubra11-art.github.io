## Concept

The prototype demonstrates a possible digital service workflow:

1. A process alarm is generated by the machine.
2. The alarm is displayed on the HMI.
3. An operator scans a QR code.
4. The device ID and alarm ID are transferred to the troubleshooting page.
5. The operator performs guided diagnostic checks.
6. The results are documented.
7. A structured service case can be created.
8. The service team receives the relevant information for follow-up.

## Example architecture

Process equipment

→ Siemens PLC

→ QR / Error Code

→ Secured Service Portal

→ FRINGS Service

## Production considerations

A production implementation should include:

- HTTPS
- Authentication and authorization
- Role-based access control
- Secure API communication
- OT/IT network segmentation
- Audit logging
- Data retention policies
- Secure device identification
- Service-case history
- Monitoring and error handling

The prototype deliberately does not implement these production components.

## Technical implementation

The current prototype is intentionally lightweight and can run as a static GitHub Pages website.

No backend is required.

The demo uses:

- HTML
- CSS
- JavaScript
- Browser localStorage
- QRCode.js

The service email function creates a local `mailto:` draft.

No machine data is transmitted to a server.
